# CSMS JavaScript Project Overview

## Project

The **Community Services Management System (CSMS)** is a semester-long software development project used in the Programming Languages Laboratory.

Instead of completing unrelated programming exercises, students continuously develop one application throughout the semester.

The project demonstrates how programming language concepts are applied within a structured software development environment.

## Project Domain

CSMS represents a simplified community services platform.

The system will gradually introduce domain concepts such as:

- Residents
- Service Requests
- community services
- request processing
- status management
- validation
- persistence
- application services
- HTTP interaction
- user interface behavior

Not all capabilities are available in the starter repository.

They will be introduced incrementally through Moodle activities and development tickets.

## JavaScript Implementation

This repository implements CSMS using:

- JavaScript
- Node.js 24
- Express.js 5
- EJS
- npm
- Node.js built-in test runner
- Supertest

The application uses ES modules.

## Semester Development Model

Development follows an incremental sprint-based approach.

Each activity may introduce:

- a domain concept
- a programming language concept
- an architectural responsibility
- automated tests
- validation rules
- persistence
- application behavior
- API behavior
- user interface behavior

Students should implement only the requirements assigned for the current activity.

## Why the Project Is Incremental

Professional software is rarely completed in a single programming session.

The project therefore emphasizes repeated development cycles:

1. Understand the requirement.
2. Update the stable project baseline.
3. Create a feature branch.
4. Implement a focused change.
5. Test the change.
6. Review the implementation.
7. Commit the work.
8. Push the branch.
9. Create a Pull Request when required.
10. Integrate reviewed work according to the activity instructions.

Later activities build upon earlier work.

Throughout the semester, students are expected to develop competence in:

- debugging
- Git
- GitHub

- code review
- software documentation
- incremental software development

## Development Responsibility

The repository provides the development environment and architectural starting point.

The student is responsible for implementing assigned functionality.

Starter files may therefore be intentionally incomplete.

An incomplete class, service, repository, utility, or controller does not necessarily indicate a defect in the starter repository.

Before modifying a file, determine whether the current Moodle activity requires that modification.

## Source of Requirements

The authoritative requirements for student work are the current:

- Moodle activity
- development ticket
- instructor instructions

Repository documentation explains the project and development process but does not replace activity-specific requirements.

## Expected Outcome

By the end of the semester, the repository should represent the student's progressively developed implementation of the Community Services Management System.

The Git history should also demonstrate how that implementation evolved through the semester.
